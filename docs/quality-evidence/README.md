# Quality evidence index (main-quality line)

Every figure here is generated by a committed script from real run artifacts.
No figure is hand-drawn. Each entry lists its claims, its generator, and the
exact command to re-derive it. Run everything from the repo root with
`uv run python` (evidence deps: `uv pip install matplotlib manifold3d scipy rtree shapely`).

Campaign data lives outside the repo (scratch): runs keep `environment.json`
once, `verdict.json` + full `result.json` per cell. The fingerprint inside
each result names the git rev, per-prompt sha8 hashes and the kernel that
produced it. A verdict without a fingerprint is not evidence.

## increment-12 — topology repair guidance (measured A/B on legacy family)
- Change: the multi-component gate failure now names the construction
  method (union every member; attached members must overlap body volume,
  not touch the surface) instead of only reporting the symptom.
  Designer prompt already banned floating parts; the repair round had no

  not per-case hints.
- Measurement (A/B vs increment-10, cache OFF): overall accepted 8/21 ->

  visually correct (grille+headlights reproduced, genus 7/2, handle loop
  right) yet failed on pen-count feature demand. Next lever: soften
  feature demand on no-GT freehand without weakening it on benchmark.

## increment-13 — registered-view contract: aspect + rescue-rotation gates
- Trigger: user audit found the accepted lamp builds wrong (base built as
  a rectangular box where a wide-side-down trapezoid was drawn; shade
  inverted) — every gate had passed. Machine autopsy: projections sat at
  sim 0.497 vs the 0.45 floor, reachable only by rotating the drawn crop
  50 deg; `source_aspect` 1.40 vs `rendered_aspect` 0.93 (51% mismatch)
  was published by the evaluator and read by NO gate; the normalized
  silhouette IoU (both masks resized to the same 96-box) is structurally
  blind to exactly this class.
- Change: per registered view, |source_aspect/rendered_aspect − 1| <= 0.40
  (clean-accepted p90 = 0.04), and pose rotation > 15 deg must reach
  sim >= 0.55; violations fail `projections` naming view and numbers.
  Planted-helper tests (wide disc built edge-on, rescue rotation at .47,
  genuine 35-deg tilt at .80 passes).
- Full re-score through the product path: 117 cells, 13 flips, all
  accept->reject, all on never-verified cells: lamp x6 (the user's
  finding), 102 x3 (rot-45 rescue; 3.56x volume case anyway), rocket t3
  (bullet+plate, no fins — vision-confirmed defective), flower t1/t3
  (head built on the wrong plane vs the registered front crop), scooter
  t1 (interior gate: deck drawn with tread lines, built plain).
- Lesson recorded: warm-cache arms print ONE trial three times — the
  baseline lamp "3/3 accepted" was one cached wrong build (bit-identical
  sims across trials are the signature).

## ab-frozen-main-vs-quality — does the quality code change outcomes?
- Design: same drawing bytes (sha256-pinned), same form fields, same model
  endpoint, cache forced off, N=3 x 7 freehand cases, two real uvicorns —
  one per checkout (`main @ 2672a6d` worktree `d2c-ab-main`,
  `main-quality`); driver `scripts/ab_arm.py`, one-judge scorer
  `scripts/ab_score.py` re-runs BOTH arms' selected-attempt SCADs through
  the main-quality evaluator with the deterministic OpenCV rubric, so a
  verdict difference can only be the PART, not the grader.
- Own-gates: main accepted 7/21, quality accepted 3/21 (its own stricter
  stack rejects what main lets through).
- One judge: main 4/21, quality 2/21. main's 7 self-accepts contained
  3 confirmed false accepts (person t1 wrong-plane build, aspect 0.60 vs
  0.40; scooter t2/t3 fill-over — interior gate). quality's self-accepts:
  initially 3, but the judge + independent vision pass caught ONE false
  accept of quality's own (lamp t2: tipped shade rescued by a -35-deg
  crop rotation at sim 0.567 under the 0.55 rescue floor).
- Fix from the field: rescue-rotation floor 0.55 -> 0.70, calibrated on
  the accept distribution (all genuine accepts matched at rot 0, sim
  0.48-0.88; genuine tilts reach 0.80), fixture added
  (test_gate_integrity tipped-lamp case). Re-judge: main 4/21, quality
  2/21, zero false accepts among quality's own accepts.
- Also honest about N: person quality-t3 = model returned no content
  (RuntimeError) — real generation failure, counted as not accepted.
  Rate difference (4 vs 2 of 21) is inside noise at N=3; the difference
  that is NOT noise is purity: 3/7 main accepts were broken parts wearing
  a green stamp, 0/3 after the quality stack's final hole was closed.
- Conclusion: the new code does not raise the generation ceiling (same
  model); it removes false green stamps. Generation-rate improvements
  need the model-side or scaffolding experiment, not more gates.
