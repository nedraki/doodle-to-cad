# bench-revolve — focused revolution-family comparison (#95)

Question this answers: does the new bounded `revolve` operation change
outcomes on the rotation family (user-approved scope: vase, stepped/hex knob,
cylinder-like case, both backends, reusing frozen `bench-final` numbers for
the other 19 cells)?

Protocol: same certified controls as the frozen plan — `scripts/evaluate_brep.py
trials --plan ../bench-final/TRIAL-PLAN.json --trials 3 --cell …` (certified
dimensions/notes copied verbatim; openscad asked_missing_dimensions=false),
in-process app on 127.0.0.1:8136, resume-safe rows under `runs/`.
Tested commit `88fa0ec` (branch tip at implementation); each trial dir holds
an `environment.json` (harness #85) with tested_commit, server model
`local-inference-lab/Qwen3.8-Flash-Next-NVFP4`, worker venv, package versions.
Product code diff vs baseline touched only revolve surfaces
(`revolve_profile.py`, `brep_recipe.py`, `workers/brep/build.py`, three
prompt files +1 line each); no openscad-path file changed, so openscad rows
are a control, not a treatment.

## What changed and what did not

- Construction class is now correct: **all 8 built usd-brep rows pass
  genus_pass** (002: 3/3 genus-0 hollow vessel; 006/009 knobs correct
  silhouette topology; 009 trial-03 also passes volume_pass AND fidelity_pass).
  Baseline: the vase built nothing (unsupported_construction /
  unresolved_design), hex knob nothing, stepped knob 1 of 2.
- What still fails is **ink fidelity, not construction**: extents_fail +
  volume_fail on the vase = belly thinner than drawn (live demo measured
  80–90 mm vs GT 102.5 mm, wall honoured). `overall_pass` stays 0/3 across
  the family; that number measures silhouette fidelity, not the revolve gap.
- 2 error rows (006 trial-02, 009 trial-01) `invalid_recipe` — detail:
  "Construction plan rejected: Unsupported clarification or unknown feature".
  That is the upstream construction-plan gate (model planning), the same
  failure family as baseline knob trial-2; the new revolve validator never
  ran for these rows (no recipe reached validation).
- openscad control: build rates and mean scores match its frozen baseline
  within n=3 noise (e.g. vase 2/2 accepted mean 94.3 → 3/3 mean 98.2),
  consistent with zero openscad-path code changes.

## Limits

n=3 per cell, one local model, one run; `unverified` usd-brep verdicts await
user review (this bench is machine checks only, no user acceptance data —
absent, never derived). GT references are the frozen
`references/reference-measurements.json`; no reference values were edited.
